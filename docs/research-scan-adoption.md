# How the additional engineering scan changed MnemoGraph

The user supplied this scan as conversation text on 18 October 2026. Its product examples use the name Relay. This file records the mapping into MnemoGraph; it does not silently rename the project or treat quoted implementation directions as authorization. The [primary-source review](research-v2-source-review.md) distinguishes verified identities and methods from unverified claims.

| Scan idea | What we adopted | What we did not claim |
| --- | --- | --- |
| Oracle typed memory links | Six validated lifecycle relationships and bounded neighborhood traversal | Oracle SDK integration or automatic correct link inference |
| GraphMemix evidence forests | Connected evidence paths and deterministic bounded selection, with a forest receipt | Full optimizer, generative verification or paper benchmark reproduction |
| Arize small current file | A compact current startup view with accepted handles, tasks and checkpoint | An 8,000-character user file or complete always-loaded profile |
| Google event/revision separation | Exact source messages separate from claims; revisioned heads and history | Managed Memory Bank integration, TTL worker or automatic rollback |
| Anthropic Dreams | Maintenance inspection stays outside active answering and never rewrites accepted content | A scheduled LLM consolidation job |
| AWS typed ingestion | Separate exact message, candidate, explicit memory, checkpoint and task operations | JSON being automatically trustworthy or bypassing every extraction stage |
| Provenance-aware citation lock | Source pointers, exact hashes, versions and expansion receipts; model adapter tracks opened handles | A proven answer verifier or claim that a model cited only valid evidence |
| Mem0 fused retrieval | Lexical BM25/TF-IDF anchors followed by graph ranking | Mem0 integration or equivalent neural embeddings |
| Zep context views | Explicit query intents and historical/current source views | Full Graphiti implementation or complete intent-specific task query language |
| Filesystem role separation | Client proposes; service validates; retriever constructs evidence | Separate autonomous manager/search/execution agents |
| Selective forgetting | Archived/superseded eligibility plus a distinct live-store forget operation | Automatic utility pruning or forensic deletion of backups |
| Medium staging/evaluate/promote | Candidate endpoint always writes asserted state; promotion requires authorization and version check | A benchmark-gated asynchronous promotion pipeline |
| Cloudflare explicit remember | SDK/MCP explicit writes coexist with exact raw conversation events | Automatic extraction from an attached account |

The largest consequence is that a write is a governed state change. The service records who wrote it, what source it references, which version it replaces and who can read it. The UI shows those same records. A source path proves origin; it cannot prove the source was right.

The scan's vendor performance figures are not measurements of this repository. X and Medium posts remain useful design leads, with lower evidence weight than a checked paper or official API specification. The local comparison uses named implementations from this codebase and reports their failures, including the missing-fact retrieval problem.

The five engineering sources verified in the targeted review were Oracle, Arize, Google, Cloudflare and AWS. Publication identities for the supplied 18-paper synthesis also resolved. Other announcements and social posts in the additional scan were not exhaustively verified. Adopted ideas are engineering adaptations, not claims of independent novelty.
