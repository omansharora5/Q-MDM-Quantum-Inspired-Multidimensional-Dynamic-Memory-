Connect your agent to this memory service

This browser is the dashboard. Your agent runs separately and calls the same local memory service. Follow the steps below; no model-provider key is needed by the memory service.

  1. 01
    Pick your agent
  2. 02
    Prepare an agent identity and test access

    Every agent gets its own workspace key. Run this PowerShell block in the terminal you will use to launch the agent. It loads the selected identity locally and tests the API; it does not start a model.

  3. 03
    Add the configuration below, then start your agent

    Use the configuration for the platform you selected. Ask the agent to call memory_connect and memory_state. This page checks for its matching heartbeat.

    Waiting for an agent connection. The dashboard heartbeat does not count.

Use a separate scoped key for each agent. Keys live in .local/keys.json. These templates do not change your host configuration. REST is an HTTP API; the MCP bridge uses stdio. This service does not expose HTTP MCP.

AGENT LIFECYCLE
  1. Connect & load stateReport platform, task, and heartbeat.
  2. Recall smallSearch for handles within a context budget.
  3. Expand when neededRead the source before making a claim.
  4. Remember & hand offSave evidence. Use versions for updates.

Tool access does not automatically capture conversations or force the model to use memory. Add the lifecycle policy to your agent instructions.
